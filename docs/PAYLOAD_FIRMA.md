# G3 payload FIRMA

Status: recommendation prepared; human FIRMA not yet given.

## Recommended payload

**ふたりの読書星図 / Reading Constellation**

A private reading space where two people can see how the same or different
books connect through themes and feelings, then receive a next-book
recommendation with traceable reasons.

## Why this workpiece

- It is a real product promise, not a second explanation of VERROCCHIO.
- Its relationship map gives the three-minute demo a visual reveal.
- Explainable two-person recommendations give GPT-5.6 a meaningful product
  role rather than a decorative chat box.
- A substantial local implementation already exists at
  `/workspace/dev/apps/reading-constellation`, including the clickable
  prototype, graph engine, recommendation engine, API, tests, and deployment
  tooling.
- Reusing a working asset obeys VERROCCHIO's scope ratchet and lowers deadline
  risk.

## Proposed commission

> Turn two independent reading histories into one explorable constellation,
> then use GPT-5.6 to explain the bridge to the next book without flattening
> either person's taste.

## Bounded adaptation

1. Copy the existing workpiece into the hackathon workspace without altering
   its original source.
2. Cut the judge journey to: choose person → open constellation → reveal one
   connection → ask for the next bridge book.
3. Pin the runtime product insight to `gpt-5.6-sol` and record its response ID
   and evidence.
4. Provide deterministic sample data and a fallback so the judge path never
   depends on private accounts.
5. Run the existing test and deployment checks, then record the result through
   VERROCCHIO's CARTONE and EVIDENCE paths.

## Explicit exclusions

- No generalized social reading network.
- No new billing, marketplace, or public profile system.
- No rewrite into a new framework.
- No redesign of every existing screen.
- No production migration of private family data.

## Alternatives rejected

| Candidate | Reason |
| --- | --- |
| A standalone FIRMA approval inbox | Too close to VERROCCHIO; the pair would look like one idea repeated twice |
| A brand-new consumer app | High deadline risk and weak self-proof because the useful existing work would be discarded |
| VERROCCHIO alone as both system and payload | Self-reference would remain clever but would not prove that the workshop can direct a distinct product |

the human's WHY and is therefore an `AFFRESCO` decision.
